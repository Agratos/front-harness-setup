# 테스트벤치 — 프로젝트 관리 프로그램 (고정 사양)

하네스를 고칠 때마다 **같은 요구사항**으로 처음부터 만들게 해서, 하네스가 실제로 나아지는지 비교한다.
사양이 시행마다 흔들리면 비교가 성립하지 않으므로 **아래 사양은 절대 수정하지 않는다.**

## 시행 범위 (v1 — 2026-08-10 확정)

**1 시행 = 부트스트랩 + step 01 완주**(AC-1~AC-4를 E2E 단언으로 통과).
step 02·03 은 사양에 남겨두되 반복 시행에서는 돌리지 않는다.

이유: 하네스 마찰은 압도적으로 **부팅~첫 화면 구간**에 몰려 있다(시행 1에서 발견한 6건이 전부 이 구간).
step 02·03 은 같은 절차의 반복이라 새 정보를 거의 주지 않으면서 시행 비용을 3배로 만든다.
**비교 가능성이 반복 시행의 전부**이므로, 좁고 동일한 범위를 4회 도는 편이 낫다.
범위를 바꿔야 한다면 시행 전에 바꾸고 여기에 기록한다 — 시행 중 변경 금지.

## 시행 규칙

1. 매 시행은 `node scripts/copy-project.mjs` 로 만든 **새 폴더**에서 시작한다 (이전 산출물 0).
2. 아래 사양을 **그대로** 투입한다. 시행마다 요구사항을 바꾸지 않는다.
3. **시행 중에는 하네스를 고치지 않는다.** 발견 사항은 기록만 하고, 시행이 끝난 뒤 본체에 반영한다.
   (고치면서 돌리면 무엇이 개선을 만들었는지 알 수 없다.)
4. 시행이 끝나면 `docs/testbench/results.md` 에 계측값을 기록한다.

## 사양 (고정)

프로젝트의 할 일(태스크)을 등록·추적하는 단일 페이지 웹앱. 서버 없이 클라이언트 상태로 동작한다.

**페르소나** — 소규모 팀 리더 "정민". 팀원 3~4명의 할 일을 한 화면에서 보고 상태를 갱신하려 한다.

### step 01-task-board — 태스크 등록·목록

| AC | 수용기준 |
| --- | --- |
| AC-1 | 제목·담당자·우선순위(높음/보통/낮음)를 입력해 추가하면 목록 카드가 1개 늘어난다 |
| AC-2 | 추가 직후 입력 폼의 모든 필드가 비워진다 |
| AC-3 | 제목이 비어 있으면 추가되지 않고 안내 문구가 보인다 |
| AC-4 | 태스크가 0건이면 빈 상태 안내가 보인다 |

### step 02-status-flow — 상태 전이·통계

| AC | 수용기준 |
| --- | --- |
| AC-5 | 각 카드에서 상태를 `할일 → 진행중 → 완료` 로 바꿀 수 있다 |
| AC-6 | 상단 통계(전체·진행중·완료 건수)가 상태 변경 즉시 반영된다 |
| AC-7 | 완료된 태스크는 카드에 완료 표시가 보인다 |

### step 03-filter-search — 필터·검색

| AC | 수용기준 |
| --- | --- |
| AC-8 | 상태 필터(전체/할일/진행중/완료)로 목록이 걸러진다 |
| AC-9 | 제목 검색어로 목록이 걸러진다 |
| AC-10 | 필터 결과가 0건이면 "조건에 맞는 태스크가 없습니다" 가 보인다 |

> 복잡도: 폼 필드 3개 이상 · 상태 분기 4개 이상(빈/입력오류/필터0건/완료) · 관여 슬라이스 3개 이상
> → CEO 복잡도 체크리스트 2개 이상 해당 = **복잡 화면 → 페르소나 2~3**.

## 계측 지표 (매 시행 기록)

| 지표 | 왜 보는가 |
| --- | --- |
| **사람 개입 횟수** | ⭐ 핵심 — "알아서 개발"이 되는가. 오케스트레이터가 막혀 사람이 손댄 횟수 |
| **AC 달성** (/10) | ⭐ 핵심 — 요구사항을 실제로 충족했는가 (E2E 단언으로 확인된 것만 인정) |
| 완주 여부 | status=done 도달 |
| 사이클 수 | `loop.mjs` 총 호출 수 |
| 재작업 횟수 | `reworkCount` 합계 |
| blocked 발생 | 자동 복구 실패 횟수 |
| 게이트 실패 | 결정적 게이트 탈락 횟수 |
| 최종 평가 | score / major 불만 |
| **가짜 통과** | ⭐ 구현 없이 통과한 step 수 (0이어야 함) |
| 하네스 결함 발견 | 이 시행에서 새로 드러난 하네스 문제 수 |

**개선의 정의**: 시행이 거듭될수록 `사람 개입 ↓`, `AC 달성 ↑`, `가짜 통과 = 0 유지`, `하네스 결함 발견 ↓`.
사이클 수는 늘어도 무방하다(더 꼼꼼해진 것일 수 있음) — 품질 지표가 우선이다.
